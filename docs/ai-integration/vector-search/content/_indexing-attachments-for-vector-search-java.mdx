<Admonition type="note" title="">

### Attachments in RavenDB
    
---    

* Attachments in RavenDB allow you to associate binary files with your JSON documents.  
  You can use attachments to store images, PDFs, videos, text files, or any other format.  

* Attachments are stored separately from documents, reducing document size and avoiding unnecessary duplication.
  They are stored as **binary data**, regardless of content type.

* Attachments are handled as streams, allowing efficient upload and retrieval.  
  Learn more in: [Attachments overview](../../../document-extensions/attachments/overview.mdx).

</Admonition>

<Admonition type="note" title="">

### Indexing attachment content for vector search
    
---    

You can index attachment content in a vector field within a static-index,    
enabling vector search on text or numerical data that is stored in the attachments.

Only **local attachments** can have their content indexed.  
[Remote attachment](../../../document-extensions/attachments/store-attachments/store-attachments-remote.mdx) content is unavailable during indexing.  
The examples below skip remote attachments.

* **Attachments with TEXT**:  
    * During indexing, RavenDB processes the text into a single embedding per attachment using the built-in  
      [bge-micro-v2](https://huggingface.co/TaylorAI/bge-micro-v2) model.

* **Attachments with NUMERICAL data**:  
    * While attachments can store any file type, RavenDB does Not generate embeddings from images, videos, or other non-textual content.  
      Each attachment must contain a **single** precomputed embedding vector, generated externally.  
    * RavenDB indexes the embedding vector from the attachment and can apply [quantization](../../../ai-integration/vector-search/quantization.mdx)
      (e.g., index it in _Int8_ format) if this is configured.  
    * All embeddings indexed within the same vector-field in the static-index must be vectors of the **same dimension** to ensure consistency in indexing and search.
      They must also be created using the **same model**.

</Admonition>

<Panel heading="Indexing TEXT attachments">
 
* The following index defines a **vector field** named `VectorFromAttachment`.

* It indexes embeddings generated from the text content of the `description.txt` attachment.  
  This applies to all _Company_ documents that contain an attachment with that name.

<Tabs groupId='languageSyntax'>
<TabItem value="AbstractIndexCreationTask" label="AbstractIndexCreationTask">
```java
public class Companies_ByVector_FromTextAttachment extends AbstractIndexCreationTask {
    public Companies_ByVector_FromTextAttachment() {
        map = "from company in docs.Companies " +

            // Load the attachment and skip missing or remote attachments
            "let attachment = LoadAttachment(company, \"description.txt\") " +
            "where attachment != null && " +
            "      attachment.RemoteFlags.ToString() == \"None\" " +

            "select new " +
            "{ " +
            // Index the text content from the attachment in the vector field
            "    VectorFromAttachment = " +
            "        CreateVector(attachment.GetContentAsString(Encoding.UTF8)) " +
            "}";

        // Configure the vector field:
        FieldVectorOptions vectorOptions = new FieldVectorOptions();

        // Specify 'Text' as the source format
        vectorOptions.setSourceEmbeddingType(VectorEmbeddingType.TEXT);

        // Specify the desired destination format within the index
        vectorOptions.setDestinationEmbeddingType(VectorEmbeddingType.SINGLE);

        vectorOptionsStrings.put("VectorFromAttachment", vectorOptions);

        searchEngineType = SearchEngineType.CORAX;
    }
}
```
</TabItem>

### LINQ index

* The following index defines a **vector field** named `VectorFromAttachment`.  

* It indexes the precomputed embedding vector stored in the `vector.raw` attachment.  
  This applies to all _Company_ documents that contain an attachment with that name.

* Each attachment contains raw numerical data in 32-bit floating-point format.  

<Tabs groupId='languageSyntax'>
<TabItem value="AbstractIndexCreationTask" label="AbstractIndexCreationTask">
```java
public class Companies_ByVector_FromNumericalAttachment
    extends AbstractIndexCreationTask {
    public Companies_ByVector_FromNumericalAttachment() {

        vectorOptions.setDestinationEmbeddingType(VectorEmbeddingType.SINGLE);
```

```java
// These vectors are simple precomputed embedding vectors
// with 32-bit floating-point values.
// Note: In a real scenario, embeddings would be generated by a model.
// ===================================================================
float[] v1 = new float[] { 0.1f, 0.2f, 0.3f, 0.4f };
float[] v2 = new float[] { 0.1f, 0.7f, 0.8f, 0.9f };
float[] v3 = new float[] { 0.5f, 0.6f, 0.7f, 0.8f };

// Prepare the embedding vectors as `byte[]` to be stored as attachments:
// =====================================================================

byte[] byteArray2 = new byte[v2.length * Float.BYTES];
byte[] byteArray3 = new byte[v3.length * Float.BYTES];

ByteBuffer.wrap(byteArray2).order(ByteOrder.LITTLE_ENDIAN).asFloatBuffer().put(v2);
ByteBuffer.wrap(byteArray3).order(ByteOrder.LITTLE_ENDIAN).asFloatBuffer().put(v3);

try (IDocumentSession session = store.openSession()) {
    // Load existing Company documents from RavenDB's sample data:
    // ===========================================================
    Company company1 = session.load(Company.class, "companies/50-A");
    Company company2 = session.load(Company.class, "companies/51-A");
    Company company3 = session.load(Company.class, "companies/52-A");

    // Store the attachments in the documents (using ByteArrayInputStream):
    // ====================================================================
    session.advanced().attachments().store(company1, "vector.raw",
        new ByteArrayInputStream(byteArray1));
    session.advanced().attachments().store(company2, "vector.raw",
        new ByteArrayInputStream(byteArray2));
    session.advanced().attachments().store(company3, "vector.raw",
        new ByteArrayInputStream(byteArray3));

    session.saveChanges();
}
```

### JS index

* The following is the JavaScript index format equivalent to the [LINQ index](#linq-index) shown above.

* The main difference is that JavaScript indexes do Not support `getContentAsStream()` on attachment objects:
  * Because of this, embedding vectors must be stored in attachments as **Base64-encoded strings**.  
  * Use `getContentAsString()` to retrieve the attachment content as a string, as shown in this example.

<Panel heading="Indexing ALL attachments">

* The following index defines a vector field named `VectorFromAttachment`.

* It indexes the precomputed embedding vectors stored in ALL local attachments of all _Company_ documents.

* This example assumes that **every local attachment** on the indexed documents contains a single embedding vector  
  stored as raw 32-bit floating-point values. All vectors must have the same number of dimensions and be generated using the same model.  
    
  If the documents also contain other attachment formats, such as text, PDFs, or Base64-encoded vectors,  
  filter the attachments by name before passing their content to `CreateVector()`.

<Tabs groupId='languageSyntax'>
<TabItem value="AbstractIndexCreationTask" label="AbstractIndexCreationTask">
```java
public class Companies_ByVector_AllAttachments extends AbstractIndexCreationTask {
    public Companies_ByVector_AllAttachments() {
        map = "from company in docs.Companies " +

            // Load ALL local attachments from the document
            "let attachments = LoadAttachments(company) " +
            "    .Where(attachment => " +
            "        attachment.RemoteFlags.ToString() == \"None\") " +

            "select new " +
            "{ " +
            // Index the attachments' content in the vector field
            "    VectorFromAttachment = CreateVector( " +
            "        attachments.Select(e => e.GetContentAsStream())) " +
            "}";

        // Configure the vector field:
        FieldVectorOptions vectorOptions = new FieldVectorOptions();
        vectorOptions.setSourceEmbeddingType(VectorEmbeddingType.SINGLE);
        vectorOptions.setDestinationEmbeddingType(VectorEmbeddingType.SINGLE);

        vectorOptionsStrings.put("VectorFromAttachment", vectorOptions);

        searchEngineType = SearchEngineType.CORAX;
    }
}
```
