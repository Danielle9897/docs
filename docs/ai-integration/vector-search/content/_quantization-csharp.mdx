<Panel heading="What is quantization">

Quantization is a technique that reduces the precision of numerical data.
It converts high-precision values, such as 32-bit floating-point numbers, into lower-precision formats like 8-bit integers or binary representations.

The quantization process, applied to each dimension (or item) in the numerical array, 
serves as a form of compression by reducing the number of bits used to represent each value in the vector.
For example, transitioning from 32-bit floats to 8-bit integers significantly reduces data size while preserving the vector's essential structure.  

Although it introduces some precision loss, quantization minimizes storage requirements and optimizes memory usage.  
It also reduces computational overhead, making operations like similarity searches faster and more efficient.

</Panel>

<Panel heading="Supported quantization formats">

For non-quantized raw 32-bit data or text stored in your documents,
RavenDB allows you to choose the quantization format for the generated embeddings stored in the index.
The quantization format applies to how vectors are stored internally in the index, regardless of the client language used to submit the data.

The selected quantization type determines the similarity search technique that will be applied.
By default, raw text processed by the built-in model and numerical embeddings supplied in `Single` format are indexed as `Single`.
For task-generated embeddings, see [Quantization and embeddings generation tasks](#quantization-and-embeddings-generation-tasks).

The available quantization options are:  

   * `Single` (a 32-bit floating point value per dimension):  
     Provides precise vector representations.  
     The [Cosine similarity](https://en.wikipedia.org/wiki/Cosine_similarity) method will be used for searching and matching.  

   * `Int8` (an 8-bit integer value per dimension):  
     Reduces storage requirements while maintaining good performance.  
     Saves up to 75% storage compared to 32-bit floating-point values.  
     The Cosine similarity method will be used for searching and matching.  

   * `Binary` (1-bit per dimension):  
     Minimizes storage usage, suitable for use cases where binary representation suffices.  
     Saves approximately 96% storage compared to 32-bit floating-point values.  
     The [Hamming distance](https://en.wikipedia.org/wiki/Hamming_distance) method will be used for searching and matching.  
      
     <Admonition type="note" title="">
     If your documents contain data that is already quantized,  
     it cannot be re-quantized to a lower precision format (e.g., Int8 cannot be converted to Binary).
     </Admonition>

</Panel>

<Panel heading="Configuring quantization in static indexes">

Configure the format of each vector field in the **index definition**:

* `SourceEmbeddingType` specifies the format of the source data.
* `DestinationEmbeddingType` specifies the format used to store the embeddings in the index.

The following index defines a vector field named `VectorFromText` for the `Products` collection.  
It generates embeddings from each product's `Name` field.  
    
The source type is `Text` and the destination type is `Int8`,  
so the embeddings are quantized to `Int8` before being stored in the index.

<Tabs groupId='languageSyntax'>
<TabItem value="LINQ_index" label="LINQ_index">
```csharp
public class Products_ByVector_Int8 :
    AbstractIndexCreationTask<Product, Products_ByVector_Int8.IndexEntry>
{
    public class IndexEntry()
    {
        // This index-field will hold the embeddings that will be generated
        // from the TEXT in the documents
        public object VectorFromText { get; set; }
    }
    
    public Products_ByVector_Int8()
    {
        Map = products => from product in products
            select new IndexEntry
            {
                // Call 'CreateVector' to create a VECTOR FIELD.
                // Pass the document field containing the text
                // from which the embeddings will be generated.
                VectorFromText = CreateVector(product.Name)
            };

        VectorIndexes.Add(x => x.VectorFromText,
            new VectorOptions()
            {
                // Define the source embedding type
                SourceEmbeddingType = VectorEmbeddingType.Text, 
                
                // Define the quantization for the destination embedding
                DestinationEmbeddingType = VectorEmbeddingType.Int8
            });

        // The index MUST use the Corax search engine 
        SearchEngineType = Raven.Client.Documents.Indexes.SearchEngineType.Corax;
    }
}
```
</TabItem>
<TabItem value="JS_index" label="JS_index">
```csharp

{

    {

            @"map('Products', function (product) {
                   return {
```

</TabItem>

<Panel heading="Quantization and embeddings generation tasks">

* When using an [embeddings generation task](../../../ai-integration/generating-embeddings/overview.mdx),
  the index receives numerical embeddings that the task has already generated and stored.

* The task's `Quantization` setting determines their stored format.  
  Configure it in [Studio](../../../ai-integration/generating-embeddings/embeddings-generation-task.mdx#configuring-an-embeddings-generation-task-from-the-studio)
  or through the `Quantization` property in the [Client API](../../../ai-integration/generating-embeddings/embeddings-generation-task.mdx#syntax).

* The index reads those stored embeddings and can apply further quantization to its indexed copy.  
  For example, a task can store `Single` embeddings while an index reads them as `Single` and stores an `Int8` copy.

---
    
<ContentFrame>    
    
### Default behavior and allowed formats

Without additional vector-field configuration, the index uses the format stored by the embeddings generation task.  
Further quantization is possible only when the task stores `Single` embeddings:

| Format stored by the embeddings generation task | Allowed formats in the index  |
|-------------------------------------------------|-------------------------------|
| `Single`                                        | `Single`, `Int8`, or `Binary` |
| `Int8`                                          | `Int8`                        |
| `Binary`                                        | `Binary`                      |

### Quantizing task-generated embeddings in dynamic queries
    
Specify the task with `UsingTask(...)`.      
  * For a task storing `Single` embeddings,   
    add `TargetQuantization(...)` to request `Int8` or `Binary` for the auto-index.
  * For a task that stores `Int8` or `Binary`, omit `TargetQuantization` or request the same format.  
    Requesting `Binary` for an `Int8` task, or `Int8` for a `Binary` task, causes an indexing error.    

In the following example:
  * The query uses the embeddings generation task defined in [this example](../../../ai-integration/generating-embeddings/embeddings-generation-task.mdx#configuring-an-embeddings-generation-task-from-the-client-api).  
    The task stores `Single` embeddings for the _Name_ field of _Category_ documents.
  * `TargetQuantization` requests the `Int8` format,  
    so the auto-index stores an `Int8` copy of the task's embeddings.

```csharp
var similarCategories = session.Query<Category>()

            .UsingTask("id-for-task-open-ai")
```

### Quantizing task-generated embeddings in static indexes

Use `LoadVector(...)` to read the task's stored embeddings.  
    
When configuring the vector field with `VectorOptions` or the builder, `SourceEmbeddingType` must match their numerical format.
A mismatch causes an indexing error. `Text` is not a valid source type for `LoadVector`.  
Choose a destination format allowed in [Default behavior and allowed formats](#default-behavior-and-allowed-formats).      

In the following example:
  * The index loads the embeddings stored by the task defined in [this example](../../../ai-integration/generating-embeddings/embeddings-generation-task.mdx#configuring-an-embeddings-generation-task-from-the-client-api).  
    The task stores `Single` embeddings for the _Name_ field of _Category_ documents.
  * `SourceEmbeddingType` is set to `Single` to match the task,  
    and `DestinationEmbeddingType` is set to `Int8`, so the index stores an `Int8` copy.

<Tabs groupId='languageSyntax'>
<TabItem value="LINQ_index" label="LINQ_index">
```csharp
public class Categories_ByPreMadeTextEmbeddings_Int8 :
    AbstractIndexCreationTask<Category, Categories_ByPreMadeTextEmbeddings_Int8.IndexEntry>
{
    public class IndexEntry()
    {
        // This index-field will hold the text embeddings
        // that were generated by the Embeddings Generation Task
        public object VectorFromTextEmbeddings { get; set; }
    }
    
    public Categories_ByPreMadeTextEmbeddings_Int8()
    {
        Map = categories => from category in categories
            select new IndexEntry
            {
                // Call 'LoadVector' to create a VECTOR FIELD. Pass:
                // * The document field name to be indexed (as a string) 
                // * The identifier of the task that generated the embeddings
                //   for the 'Name' field
                VectorFromTextEmbeddings = LoadVector("Name", "id-for-task-open-ai")
            };

        VectorIndexes.Add(x => x.VectorFromTextEmbeddings,
            new VectorOptions()
            {
                // Must match the format stored by the task
                SourceEmbeddingType = VectorEmbeddingType.Single,
                
                // The format stored in the index
                DestinationEmbeddingType = VectorEmbeddingType.Int8
            });
        
        // The index MUST use the Corax search engine 
        SearchEngineType = Raven.Client.Documents.Indexes.SearchEngineType.Corax;
    }
}
```

<Panel heading="Field configuration methods in RQL">

* In a **dynamic RQL query**, wrap the document field passed as the first argument of `vector.search` with one of the methods below.
    
* Each method specifies the source data format and the format of the embeddings stored in the auto-index.  
  For task-generated embeddings, also see [Quantization and embeddings generation tasks](#quantization-and-embeddings-generation-tasks).

    <Admonition type="note" title="">
    
    #### Available methods
        
    * `embedding.text`:  
      Generates embeddings from text as multi-dimensional vectors with 32-bit floating-point values,  
      without applying quantization.  
    
    * `embedding.text_i8`:  
      Generates embeddings from text as multi-dimensional vectors with 8-bit integer values.
    
    * `embedding.text_i1`:   
      Generates embeddings from text as multi-dimensional vectors in a binary format.
        
    * `embedding.f32`:  
      Indicates that the source data contains 32-bit floating-point embeddings (`Single`).  
      No quantization is applied. This is also the default when no wrapper is specified.
    
    * `embedding.f32_i8`:  
      Converts multi-dimensional vectors with 32-bit floating-point values into vectors with 8-bit integer values.  
    
    * `embedding.f32_i1`:  
      Converts multi-dimensional vectors with 32-bit floating-point values into vectors in a binary format.  
        
    * `embedding.i8`:  
      Indicates that the source data is already quantized as Int8  (cannot be further quantized).  
    
    * `embedding.i1`:  
      Indicates that the source data is already quantized as binary (cannot be further quantized).  
    
    </Admonition>

* Wrap the field name using any of the relevant methods listed above, based on your requirements.  
  For example, the following RQL generates embeddings from the `Name` field  
  and quantizes them to `Int8` for storage in the auto-index:

    <Tabs groupId='languageSyntax'>
    <TabItem value="RQL" label="RQL">
    ```sql
    from "Products"
    // Wrap the document field with 'embedding.text_i8'
    where vector.search(embedding.text_i8(Name), "italian food", 0.82, 20)
    ```
    </TabItem>
    </Tabs>

* In a **dynamic query over document fields containing numerical embeddings**,
  omitting a field-configuration wrapper treats the source values as **32-bit floating-point (`Single`)** embeddings and applies no quantization.  
  The following example searches such a field:

    <Tabs groupId='languageSyntax'>
    <TabItem value="RQL" label="RQL">
    ```sql
    from "Movies"
    // No wrapping
    where vector.search(TagsEmbeddedAsSingle, $queryVector, 0.85, 10)
    {"queryVector" : { "@vector" : [6.599999904632568, 7.699999809265137] }}
    ```
    </TabItem>
    </Tabs>

* In a **static-index query**, pass the existing vector field name as the first argument of `vector.search`.  
  The field-configuration wrappers listed above are not supported in this position and cause an `InvalidQueryException`.  
  RavenDB uses the field's configured source and destination formats, so an unwrapped static field can still store and search `Int8` or `Binary` vectors.  
  The following example queries the index defined in [Configuring quantization in static indexes](#configuring-quantization-in-static-indexes):

    <Tabs groupId='languageSyntax'>
    <TabItem value="RQL" label="RQL">
    ```sql
    from index "Products/ByVector/Int8"
    // Pass the vector field name without a wrapper
    where vector.search(VectorFromText, $searchTerm, 0.82, 20)
    { "searchTerm" : "italian food" }
    ```
    </TabItem>
    </Tabs>

<Panel heading="`VectorQuantizer` reference">

* `VectorQuantizer` provides client-side methods for converting 32-bit floating-point embeddings into RavenDB-compatible quantized formats. 
  Use them when preparing quantized embeddings to store in documents or supply as query vectors.

* Other quantizers may produce representations that are incompatible with RavenDB.

```csharp
using Raven.Client.Documents.Queries.Vector;

public static class VectorQuantizer
{
    // Quantizes to Int8, including the metadata required by RavenDB
    public static sbyte[] ToInt8(float[] rawEmbedding);

    // Quantizes to Binary, packing one bit per dimension into a byte array
    public static byte[] ToInt1(ReadOnlySpan<float> rawEmbedding);
}
```

</Panel>
