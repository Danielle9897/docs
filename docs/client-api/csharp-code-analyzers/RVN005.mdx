<Admonition type="note" title="">

* **RVN005** reports multi-map index classes that have no `AddMap` or `AddMapForAll` calls reachable from a constructor.

* **Default severity**: `Info`  
  **Automated code fix**: No

* In this article:
   * [Description](#description)
   * [Trigger condition](#trigger-condition)
   * [How to resolve](#how-to-resolve)
      * [Before (triggers RVN005)](#before-triggers-rvn005)
      * [After (correct)](#after-correct)
   * [See also](#see-also)

</Admonition>

<Panel heading="Description">

Every non-abstract class that derives from `AbstractMultiMapIndexCreationTask`
(or the time-series and counters variants: `AbstractMultiMapTimeSeriesIndexCreationTask`, `AbstractMultiMapCountersIndexCreationTask`)
and uses the standard `CreateIndexDefinition()` implementation must register at least one map with `AddMap` or `AddMapForAll` before the index definition is built.

Without a map, the index definition contains no maps, and deploying the index fails with "Index definition contains no Maps".

</Panel>

<Panel heading="Trigger condition">

The analyzer fires when no `AddMap` or `AddMapForAll` call is reachable from any constructor of the index class or its base classes,
including a base class from a referenced project.
A call found in one constructor or a method it calls is enough to suppress RVN005.

RVN005 still fires when maps are registered only in a method that is not reachable from a constructor,
even if that method runs before the index definition is built.

The rule does not verify that every execution path registers a map or that `AddMapForAll` finds any concrete types.

The following are not reported:
  - Abstract index classes. Their subclasses are checked instead.
  - Indexes that override `CreateIndexDefinition()`.
  - Generic index classes, and index classes that are private or protected or nested in a private or protected class.
  - Indexes whose base classes cannot be analyzed, for example a base class from a compiled assembly without generated index metadata.

</Panel>

<Panel heading="How to resolve">

Add a constructor (or update the existing one) that calls `AddMap<TSource>(…)` for each document type the index should map.
Alternatively, use `AddMapForAll<TBase>(…)` to register maps for concrete types assignable to `TBase` in the assembly that defines `TBase`.

---

### Before (triggers RVN005)

```csharp
public class Animals_ByName : AbstractMultiMapIndexCreationTask
{
    // No AddMap call anywhere - RVN005 fires on the class name
}
```
<br/>

### After (correct)

```csharp
public class Animals_ByName : AbstractMultiMapIndexCreationTask
{
    public Animals_ByName()
    {
        AddMap<Cat>(cats => from c in cats select new { c.Name });
        AddMap<Dog>(dogs => from d in dogs select new { d.Name });
    }
}
```

</Panel>
